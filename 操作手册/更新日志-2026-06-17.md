## 出问题时优先检查

1. 如果提示“后台窗口已断开”
   - 重新点击“打开后台窗口”。
   - 登录后再点“检查登录状态”。
   - 不要关闭被工具接管的后台窗口。

2. 如果又出现内置浏览器文案
   - 检查 `页面/index.html` 和 `页面/app.js` 是否被旧版本覆盖。
   - 搜索关键词：内置登录窗口、工具内置浏览器。

3. 如果 APK 上传后卡住
   - 优先检查 `scripts/import-games.mjs` 中：
     - `closeApkManagerDialog`
     - `clickPrimaryApkManagerCloseButton`
     - `waitForBackToGameDetailAfterApkManager`
   - 后台按钮关键文本为：关闭。

4. 如果仅 APK 包游戏没有继续提交
   - 检查是否已成功进入游戏详情页。
   - 检查是否已进入安装包管理。
   - 检查安装包上传完成后是否成功关闭弹窗并回到详情页。

5. 如果并发不稳定
   - 先将正式执行测试缩小到 2-3 个游戏。
   - 不建议一次直接选满 10 个做首次验证。
   - 如后台本身对多窗口/多页面上传有限制，应降低并发或改成稳定队列。

## 追加修复 - 15:40 左右

### 最新日志结论

查看 `任务日志-20260617-153122.txt` 后确认：

1. 本次正式执行同时启动了多个任务，但它们共用同一个后台浏览器和同一个调试端口。
2. 多个任务同时操作同一个后台页面时，下拉框、弹窗、文件上传窗口容易互相影响。
3. 日志里出现“只有其中一个任务完整完成，其余任务卡在选择游戏类型或页面断开”的情况，符合多标签共用同一后台窗口导致互相抢占的表现。
4. APK 上传包流程里，“保存上传包信息并关闭弹窗”在 70 秒时超时，但后续日志又显示过了一会儿才点击到“关闭”，说明后台上传/关联完成后还有一段延迟，原超时保护偏短。

### 本次修复

1. 暂时关闭当前后台窗口模式下的并发
   - 正式执行和测试执行都改为单任务顺序执行。
   - 目的是先保证稳定跑完整链路，避免多个标签同时抢同一个后台弹窗。

2. APK 上传包关闭流程增加等待
   - 进入“保存上传包信息并关闭弹窗”前，先等待 2.5 秒。
   - 点击添加弹窗“确定”后，再等待 2.5 秒，让后台有时间完成状态刷新。

3. 延长上传包关闭等待
   - “保存上传包信息并关闭弹窗”的步骤超时从 70 秒调整为 120 秒。
   - 服务端“长时间无进度自动暂停”的保护从 90 秒调整为 180 秒，避免上传包慢时被提前终止。

4. 下拉默认值匹配继续放宽
   - 当前值与目标值的别名集合有交集时，会认为已经选中。
   - 例如“网游游戏 / 网络游戏 / 网游”这类相近值，会减少误点下拉。

### 关于多浏览器并发

当前“打开后台窗口 + 接管后台窗口”模式不适合多标签并发，因为后台的弹窗、上传窗口、下拉层会互相影响。

更稳的并发方案应单独实现为“独立浏览器任务模式”：

- 每个任务使用独立浏览器窗口或独立浏览器用户目录。
- 每个任务独立页面、独立弹窗、独立文件上传。
- 需要先解决每个独立浏览器的登录态复用问题。
- 建议先做 2 个并发测试，稳定后再逐步提高上限。

当前版本先以稳定为主，恢复为顺序执行。

## 追加优化 - 15:55 左右

### 问题

用户反馈 APK 上传流程不应该固定等待。实际流程应该是：

1. APK 上传完成。
2. 页面出现平台 / 合作方式可填写区域。
3. 填写平台和合作方式。
4. 点击确定或关闭。
5. 回到游戏信息页继续提交。

查看最新日志 `任务日志-20260617-154404.txt` 后确认：

- APK 在 15:46:14 已上传完成。
- 平台和合作方式也已经识别为默认值。
- 卡住的位置不是上传本身，而是“保存上传包信息并关闭弹窗”之后等待弹窗消失 / 回到游戏信息页的判断过于保守。
- 关闭安装包管理后，代码内部和外层都在等待“回到游戏详情页”，造成重复等待。

### 修复

1. APK 上传完成检测改为条件驱动
   - 不再只等下载链接、表格行、包名、大小都满足。
   - 只要检测到平台 / 合作方式选择框已经出现并可操作，就认为可以继续填写。
   - 这样进度条完成或后台识别完成后，会更快进入填写步骤。

2. 去掉上传后的固定等待
   - 去掉上传完成后的 1.2 秒固定等待。
   - 去掉保存上传包信息前的 2.5 秒固定等待。
   - 点击确定后改成 0.5 秒轮询检测状态。

3. 优化添加弹窗关闭判断
   - 点击确定后，不再一次性等待 60 秒弹窗隐藏。
   - 改为循环检测：
     - 弹窗已关闭。
     - 安装包已出现在管理列表。
     - 当前添加弹窗已有上传成功行。
     - 出现“直接关联游戏”等后台提示时，尝试点击关闭。

4. 缩短保存上传包信息步骤超时
   - 从 120 秒降为 45 秒。
   - 现在是条件驱动，不需要长时间固定等待。

5. 修复回到游戏信息页后的卡顿
   - 安装包管理关闭函数现在只负责点击关闭。
   - 回到游戏信息页的等待统一放在外层执行，避免重复等待。
   - 回到详情页后，提交前先清理无关弹窗/遮罩，再找“提交并离开”按钮。

### 当前判断

“回到游戏信息页后卡住”的主要原因是：

- 安装包管理关闭后仍可能有遮罩或残留弹窗。
- 代码内部和外层重复等待同一个“回到详情页”条件。
- 提交按钮查找前没有先清理残留弹窗，导致定位超时。

本次已针对这三点优化。
